# 역할 분담 · 격자 분할 · 일정

> **설계 원칙**: 아무도 "메쉬 담당"이 되지 않는다.
> 3인 전원이 첫날부터 마지막 날까지 **구조 생성 → 시뮬레이션 실행 → 결과 정리**의 전체 사이클을 돈다.
> 나뉘는 것은 *작업 종류*가 아니라 *격자 위의 좌표*다.

---

## 1. 왜 이렇게 나누는가

기획서 4-6절의 원안(구조 담당 / 물리 담당 / 분석 담당)에는 두 가지 문제가 있다.

| 문제 | 결과 |
|---|---|
| **직렬 의존** — 구조 담당이 막히면 나머지 2명이 대기 | 한 명이 막히면 팀 전체가 멈춤. 1개월 일정에서 치명적 |
| **경험 편중** — 분석 담당은 TCAD 를 한 번도 안 돌려보고 끝남 | 발표 Q&A 에서 답변 가능한 사람이 1명뿐. 심사 리스크 |

**대안: 2차원 격자를 세로로 3등분한다.**
DoE 격자점 25개는 서로 완전히 독립이므로, 나누는 순간 병렬화가 되고 의존이 사라진다.

---

## 2. DoE 격자 (5 × 5 = 25점)

**X축 — DBCAT (질화막 두께)** : `24, 30, 36, 42, 48` nm (공칭 36 nm)
**Y축 — 접합 도핑 배수** : `0.30, 0.50, 0.70, 0.85, 1.00` × 베이스라인

|          | D24 | D30 | D36 | D42 | D48 |
|----------|-----|-----|-----|-----|-----|
| **N100** | 유용성 | 유용성 | ★공통 | 주수빈 | 남다연 |
| **N085** | 유용성 | 유용성 | 주수빈 | 주수빈 | 남다연 |
| **N070** | 유용성 | 유용성 | 주수빈 | 주수빈 | 남다연 |
| **N050** | 유용성 | 유용성 | 주수빈 | 주수빈 | 남다연 |
| **N030** | 유용성 | 유용성 | 주수빈 | 주수빈 | 남다연 |

★ `D36_N100` = 베이스라인 격자점. Phase 0 에서 **3명 전원이** 독립적으로 돌려 서로 대조한다.

| 담당 | 격자점 | 올릴 파일 | 추가 과제 |
|---|---|---|---|
| **유용성** | 10 (D24, D30) | `runs/유용성_D24.csv`, `runs/유용성_D30.csv` | 얇은 질화막 극단값에서 구조 생성 실패 여부 확인 |
| **주수빈** | 9 (D36, D42) | `runs/주수빈_D36.csv`, `runs/주수빈_D42.csv` | 공칭 근방 — 논문 값과 직접 대조 |
| **남다연** | 5 (D48) | `runs/남다연_D48.csv` | BTBT 모델 3종 비교 + 메쉬 수렴성 검증 |

### 교차검증 규칙 (필수)

각자 **인접 담당자의 경계 격자점 1개**를 추가로 돌린다.

| 담당 | 추가 실행 | 대조 상대 | 올릴 파일 |
|---|---|---|---|
| 유용성 | `D36_N100` | 주수빈 | `runs/유용성_교차검증.csv` |
| 주수빈 | `D24_N100` | 유용성 | `runs/주수빈_교차검증.csv` |
| 남다연 | `D42_N100` | 주수빈 | `runs/남다연_교차검증.csv` |

같은 `run_id` 가 두 파일에 있으면 **`build.py` 가 자동으로 편차를 계산**해 알려준다.
**5% 이상 차이나면 즉시 Issue 를 연다.** 환경 차이(버전, 정규화 폭, 모델 파라미터)가 있다는 뜻이고,
이걸 놓치면 등고선이 통째로 거짓말이 된다.

> 이 중복 3점은 낭비가 아니다. 발표에서 "3인 독립 실행의 재현성을 검증했다"는 완성도 근거가 된다.

## 3. 남다연의 추가 과제가 잡무가 아닌 이유

격자점이 5개로 가장 적은 대신, **모델 선택의 근거를 만드는 독립 실험**을 맡는다.

| 실험 | 내용 | 산출물 |
|---|---|---|
| BTBT 모델 비교 | `D36_N100` 을 Schenk / Hurkx / NonlocalPath 3종으로 각각 실행 | 모델별 GIDL 곡선 + "우리는 X를 쓴다, 근거는 Y" 1페이지 |
| 메쉬 수렴성 | 겹침부 국소 메쉬를 성김/중간/촘촘 3단계로 두고 GIDL 변화 측정 | 메쉬 밀도 vs GIDL 수렴 그래프 |
| BTBT on/off | 모델 켠 것과 끈 것의 Id-Vg 차이 | 모델이 실제로 작동하는지의 증명 |

발표 Q&A 에서 "왜 그 모델을 썼나요?", "메쉬는 충분한가요?"는 **거의 확실히 나오는 질문**이다.
이 결과가 그 답변의 근거이고, 심사 항목 '완성도 30점'에 직접 연결된다.

## 4. 4주 일정

### W1 (8/03 – 8/09) — Phase 0 · 전원 동일 작업

3명이 **같은 일을 각자 한다.** 분담하지 않는다.

- [ ] 베이스라인 논문 정독
- [ ] 학교 라이선스 예제 폴더에서 DRAM/BCAT/리세스 예제 존재 여부 확인 **(최우선)**
- [ ] SDE 로 BCAT 3D 구조 재현 → SVisual 단면을 논문 그림과 대조
- [ ] `D36_N100` 실행 → CSV 로 만들어 `build.py` 로 지표 확인
- [ ] 3인의 값을 서로 대조. 논문 값과 같은 자릿수·경향인지 확인
- [ ] **W1 종료 게이트**: 3인의 Vth 가 서로 5% 이내로 일치하지 않으면 W2 로 넘어가지 않는다

> 이 주가 가장 위험하다. 구조 생성에서 막힐 확률이 가장 높다.
> **8/07(목)까지 구조가 안 나오면** 즉시 팀 회의 → 격자를 3×3(9점)으로 축소하는 안을 검토한다.

### W2 (8/10 – 8/16) — Phase 1 · 1차원 단독 스윕

| 담당 | 작업 | 실행 |
|---|---|---|
| 유용성 | DBCAT 단독 스윕 (도핑 N100 고정, D24~D48 5점) | 5 |
| 주수빈 | 도핑 단독 스윕 (DBCAT D36 고정, N030~N100 5점) | 5 |
| 남다연 | BTBT 모델 3종 + 메쉬 3단계 | 6 |

- [ ] **8/16 체크포인트**: 유용성의 결과에서 DBCAT 의 GIDL 주효과가 유의미한가?
  - 유의미 (0.3 dex 이상 변화) → W3 진행
  - 미미함 → 스윕 범위 확대(20~60 nm) 또는 기획서 5-4절 시나리오 B 로 전환

### W3 (8/17 – 8/23) — Phase 2 · 2차원 DoE

- [ ] 각자 자기 열 실행 (유용성 10점, 주수빈 9점, 남다연 5점)

- [ ] **8/21까지 80% 미달 시** 격자를 5×3 으로 줄여서라도 완주 우선

## 5. 매주 화·금 30분 동기화 (온라인)

각자 3분씩만 말한다. **길게 말하지 않는 게 규칙이다.**

1. 완료한 격자점 수 / 전체
2. 막힌 것 1개
3. 다음 회의까지 할 것

나머지 논의는 전부 Issue 코멘트로. **회의에서 기술 문제를 해결하려 하지 않는다.**
