# 역할 분담 · 격자 분할 · 일정

> **설계 원칙**: 아무도 "메쉬 담당"이 되지 않는다.
> 3인 전원이 첫날부터 마지막 날까지 **구조 생성 → 시뮬레이션 실행 → 지표 추출**의 전체 사이클을 돈다.
> 나뉘는 것은 *작업 종류*가 아니라 *격자 위의 좌표*다.

---

## 1. 왜 이렇게 나누는가

기획서 4-6절의 원안(A=구조 / B=물리 / C=분석)에는 두 가지 문제가 있다.

| 문제 | 결과 |
|---|---|
| **직렬 의존** — A가 구조를 못 만들면 B, C는 대기 | 한 명이 막히면 팀 전체가 멈춤. 1개월 일정에서 치명적 |
| **경험 편중** — C는 TCAD를 한 번도 안 돌려보고 끝남 | 발표 Q&A에서 답변 가능한 사람이 1명뿐. 심사 리스크 |

**대안: 2차원 격자를 세로로 3등분한다.**
DoE 격자점 25개는 서로 완전히 독립이므로, 나누는 순간 병렬화가 되고 의존이 사라진다.

---

## 2. DoE 격자 (5 × 5 = 25점)

1개월 일정에 맞춰 기획서의 7×7(49점)을 **5×5(25점)로 축소**했다. 여유가 생기면 중간값을 추가해 7×7로 확장한다.

**X축 — DBCAT (질화막 두께)** : `24, 30, 36, 42, 48` nm  (공칭 36 nm)
**Y축 — 접합 도핑 배수** : `0.30, 0.50, 0.70, 0.85, 1.00` × 베이스라인

|            | D24 | D30 | D36 | D42 | D48 |
|------------|-----|-----|-----|-----|-----|
| **N100**   |  A  |  A  | ★공통 |  B  |  C  |
| **N085**   |  A  |  A  |  B  |  B  |  C  |
| **N070**   |  A  |  A  |  B  |  B  |  C  |
| **N050**   |  A  |  A  |  B  |  B  |  C  |
| **N030**   |  A  |  A  |  B  |  B  |  C  |

★ `D36_N100` = 베이스라인 격자점. Phase 0에서 **3명 전원이** 독립적으로 돌려 서로 대조한다.

| 담당 | 격자점 수 | 추가 과제 |
|---|---|---|
| **A** | 10 (D24, D30 열) | 저(低) DBCAT 극단값에서 구조 생성 실패 여부 확인 |
| **B** | 9 (D36, D42 열, ★ 제외) | 공칭 근방이므로 논문 값과 직접 대조 담당 |
| **C** | 5 (D48 열) | + BTBT 모델 3종 비교 + 메쉬 수렴성 테스트 (아래 3절) |

### 교차검증 규칙 (필수)

각자 **인접 담당자의 경계 격자점 1개**를 추가로 돌린다.

| 담당 | 추가 실행 | 대조 상대 |
|---|---|---|
| A | `D36_N100` | B, C |
| B | `D24_N100` | A |
| C | `D42_N100` | B |

두 사람의 GIDL 값이 **5% 이상 차이나면 즉시 Issue를 연다.** 환경 차이(버전, 정규화 폭, 모델 파라미터)가 있다는 뜻이고, 이걸 놓치면 등고선이 통째로 거짓말이 된다.

> 이 중복 3점은 낭비가 아니다. 발표에서 "3인 독립 실행의 재현성을 검증했다"는 완성도 근거가 된다.

## 3. C 담당의 추가 과제가 잡무가 아닌 이유

C는 격자점이 5개로 가장 적은 대신, **모델 선택의 근거를 만드는 독립 실험**을 맡는다.

| 실험 | 내용 | 산출물 |
|---|---|---|
| BTBT 모델 비교 | `D36_N100` 을 Schenk / Hurkx / Dynamic Nonlocal Path 3종으로 각각 실행 | 모델별 GIDL 곡선 겹친 그림 + "우리는 X를 쓴다, 근거는 Y" 1페이지 |
| 메쉬 수렴성 | 겹침부 국소 메쉬를 성김/중간/촘촘 3단계로 두고 GIDL 변화 측정 | 메쉬 밀도 vs GIDL 수렴 그래프 |
| BTBT on/off | 모델 켠 것과 끈 것의 Id-Vg 차이 확인 | 모델이 실제로 작동하는지의 증명 |

발표 Q&A에서 "왜 그 모델을 썼나요?", "메쉬는 충분한가요?"는 **거의 확실히 나오는 질문**이다.
C의 결과가 그 답변의 근거다. 심사 항목 '완성도 30점'에 직접 연결된다.

## 4. 4주 일정

### W1 (8/03 – 8/09) — Phase 0 · 전원 동일 작업

3명이 **같은 일을 각자 한다.** 분담하지 않는다.

- [ ] 베이스라인 논문 정독 + 학습자료 완독
- [ ] 학교 라이선스 예제 폴더에서 DRAM/BCAT/리세스 예제 존재 여부 확인 **(최우선)**
- [ ] SDE로 BCAT 3D 구조 재현 → SVisual 단면을 논문 그림과 대조
- [ ] `D36_N100` 실행 → Vth, SS, DIBL 추출
- [ ] 3인의 값을 서로 대조. 논문 값과 같은 자릿수·경향인지 확인
- [ ] **W1 종료 게이트**: 3인의 Vth가 서로 5% 이내로 일치하지 않으면 W2로 넘어가지 않는다

> 이 주가 가장 위험하다. 기획서 5-5절대로 구조 생성에서 막힐 확률이 가장 높다.
> **8/07(목)까지 구조가 안 나오면** 즉시 팀 회의 → 격자를 3×3(9점)으로 축소하는 안을 검토한다.
