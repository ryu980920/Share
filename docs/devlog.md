## 2026-08-02 — 첫 번째 스윕 변수를 Rfillet → DBCAT 으로 교체

- **무엇을**: 구조 변수를 코너 라운딩(Fin Fillet Radius)에서 질화막 두께(DBCAT)로 변경
- **왜**: 베이스라인 논문 원문 재검토 결과, Rfillet 은 새들핀 채널 **내부** 코너(리세스 바닥 쪽)를 가리키는 변수로, GIDL 이 실제 발생하는 **표면의 게이트-드레인 겹침 코너**와 다른 위치였다. 논문이 GIDL 과 명시적으로 연결한 유일한 구조 변수는 DBCAT.
- **부수 효과**: 구현 난이도가 오히려 낮아짐 — filleting 특수 기능 없이 표준 에치백 깊이 파라미터로 처리 가능
- **누가**: 유용성

## 2026-08-03 — 협업 구조를 정적 사이트 → private 저장소로 전환

- **무엇을**: GitHub Pages 대시보드를 폐기하고 private repo + Issues + Projects 로 이전
- **왜**: GitHub Pages 는 무료/Pro/Team 플랜에서 **무조건 공개**다. private repo 의 Pages 는 Enterprise Cloud 전용. 경진대회 전에 주제·파라미터·결과가 노출되는 위험을 감수할 수 없다. 클라이언트 사이드 로그인은 소스가 그대로 보이므로 보안이 아니다.
- **누가**: 유용성

## 2026-08-03 — 역할 분담을 "작업 종류"에서 "격자 좌표"로 변경

- **무엇을**: 기획서 4-6절의 A=구조 / B=물리 / C=분석 분담을 폐기. 2차원 격자를 열 단위로 3등분
- **왜**: (1) 직렬 의존 — 구조 담당이 막히면 나머지 2명이 대기. 1개월 일정에서 치명적. (2) 경험 편중 — 분석 담당은 TCAD 를 한 번도 안 돌려보고 끝나 발표 Q&A 대응이 1명으로 좁아짐. 격자점 25개는 서로 완전히 독립이므로 나누는 순간 병렬화되고 의존이 사라진다.
- **대가**: 3명이 각자 전체 워크플로를 익혀야 해서 W1 학습 비용이 커진다. 이를 감수하는 대신 W1 을 전원 공통 학습 주간으로 배정
- **누가**: 유용성

## 2026-08-03 — DoE 격자를 7×7 → 5×5 로 축소

- **무엇을**: 49점 → 25점
- **왜**: 마감이 8월 말(약 4주). 3D 시뮬레이션 1회 시간을 아직 모르는 상태에서 49점은 위험. 5×5 로 완주한 뒤 여유가 생기면 중간값을 추가해 7×7 로 확장하는 방향이 안전하다.
- **재검토 시점**: W2 종료 시 1회 실행 시간 실측 후
- **누가**: 유용성

## 2026-08-03 — 결과 공유 단위를 "격자점 폴더" → "스윕 CSV 한 장" 으로 변경

- **무엇을**: `runs/D24_N030/idvg.csv` 처럼 격자점마다 폴더를 만들던 방식을 폐기.
  `runs/유용성_D24.csv` 한 파일에 여러 격자점을 long 형식으로 쌓는 방식으로 교체.
  `extract.py` + `merge.py` 를 `build.py` 하나로 통합.
- **왜**: 스윕 한 번 돌리고 폴더 5개를 손으로 만드는 것이 직관에 어긋난다.
  Workbench 스윕은 한 번에 여러 노드를 뱉는데, 그걸 사람이 쪼개서 폴더에 나눠 담는 건
  기계가 할 일을 사람에게 시키는 것. 파일 하나 = 커밋 하나 = PR 하나가 훨씬 자연스럽다.
- **부수 효과**: 담당자를 파일 이름 앞부분으로 자동 인식하게 되어 `run.yaml` 메타데이터가 불필요해졌다.
- **누가**: 유용성

## 2026-08-04 — 프로젝트 주제를 BCAT DRAM → FinFET + Embedded SiGe S/D 로 전환

- **무엇을**: 이 로그의 이전 항목들이 다루는 BCAT×doping GIDL 최적화 프로젝트를 폐기하고,
  FinFET + Embedded SiGe Source/Drain 응력공학(Ge 조성 × 리세스 깊이, 결함 발생 경계 지도)으로
  주제를 전환. 주수빈 팀원 이탈로 3인 → 2인(유용성·남다연) 체제로 축소.
  README/PROMPT/ROLES/baseline/analysis/runs/index.html/tasks.js 전체를 새 주제로 재작성.
- **왜**: 팀 구성 변경과 주제 재선정이 별도 대화에서 먼저 결정됐고, 그 결정을 레포에 반영.
  DoE 축(구조 변수 × 도핑배수 → Ge% × 리세스 깊이), 목표(최적화 → 결함 경계 트레이드오프 지도),
  베이스라인(논문 재현 → Synopsys 예제, 대응관계 미검증 명시)이 모두 바뀌었다.
- **부수 효과**: `runs/`의 결과 공유 방식(스윕 CSV 한 장 + SWB 변수표 자동 인식)은 그대로 유지 —
  이 부분은 주제와 무관하게 유효한 설계였음. 다만 지표가 GIDL/Vth/SS/DIBL 계열에서
  stress_GPa/mobility_gain_pct(wide-format, 격자점당 한 줄)로 바뀌어 `build.py`의 곡선 보간 로직은
  전부 제거하고 단순 집계로 교체. 결과 제출에 소자 사진·Id-Vg 커브·메모 첨부(`runs/attachments/`)와
  대시보드 체크박스 진행상황(`analysis/progress.json`)이 새로 추가됨. 이전 방식(`runs/_template`,
  `적용하기.sh` 등 과거 마이그레이션 스크립트)은 정리.
- **누가**: 유용성 (AI 도구와 함께 레포 재작성)

## 2026-08-04 — 팀 구성이 2인 → 3인(주수빈 재합류)으로 환원

- **무엇을**: 위 항목에서 3인→2인으로 줄었던 팀이 주수빈 재합류로 다시 3인(유용성·주수빈·남다연)이 됨. 격자 열 분할을 2등분 → 3등분(낮은/중간/높은 Ge%)으로 되돌리고, 교차검증 규칙(중간 열 담당이 양쪽 인접 열과 교차검증)·개별 추가 과제(주수빈 = Sentaurus 버전/라이선스 옵션 확인 신규 배정)·PR 승인 인원(1명→2명)·과제 카드 번호(17개→21개)를 전부 3인 기준으로 재조정. README/PROMPT/ROLES/baseline/params.yaml·make_dummy_data.py/index.html/tasks.js 전체 반영.
- **왜**: 팀 구성 변경이 별도 대화에서 먼저 결정됐고, 그 결정을 레포에 반영. 2인 체제에서 쓰던 "축 하나씩 1인 담당" 방식(Ge% 스윕/리세스 스윕을 각 1명씩)은 3인에서는 유용성·남다연이 Ge% 스윕을 나눠 맡고 중간 열(공칭 Ge% 포함) 담당인 주수빈이 리세스 스윕 전체를 대표하는 구조로 재설계.
- **부수 효과**: `analysis/build.py`·`contour.py`는 담당자를 CSV 파일명에서 그때그때 읽는 구조라 코드 변경 없이 인원 변화를 그대로 수용함 — 대시보드(`index.html`)와 문서만 재작성하면 됐다. `make_dummy_data.py`의 담당자-열 분할 로직만 2등분에서 균등 3등분(np.array_split 방식)으로 교체.
- **누가**: 유용성 (AI 도구와 함께 레포 재작성)
