## 만들어야 할 것

### 1) 변경 요약 (3줄)

- 무엇을
- 왜
- 이 변경이 **기존 결과에 영향을 주는가** ← 가장 중요

### 2) ⚠️ 영향 범위 판정

아래를 판단해서 명확히 알려라.

- [ ] 이 변경으로 **기존에 돌린 격자점을 다시 돌려야 하는가?**
  - `baseline/` 의 구조·물리·바이어스 변경 → **전부 재실행 필요**
  - `analysis/config.yaml` 변경 → 재실행은 불필요하지만 `extract.py --all` 재추출 필요
  - `analysis/*.py` 의 표시·출력만 변경 → 영향 없음
- [ ] 리뷰어가 몇 명 필요한가 (`baseline/` 이면 2명, 아니면 1명)

**재실행이 필요한데 그걸 안 알리면 3명의 결과가 조용히 섞인다.** 반드시 명시할 것.

### 3) PR 본문 초안

`.github/pull_request_template.md` 형식. "무엇을 했나"에 위 요약을,
"이상한 점 / 리뷰어가 봐줬으면 하는 것"에 영향 범위 판정을 넣는다.

### 4) devlog 항목 초안

`docs/devlog.md` 에 추가할 항목. 형식:

```markdown
## YYYY-MM-DD — 제목

- **무엇을**:
- **왜**:
- **대가/리스크**:
- **누가**:
```

**"왜"를 빼먹지 마라.** 3주 뒤에 왜 그랬는지 아무도 기억 못 한다.
